# 票据投递回执台设计

名单快照由收件人、渠道版本、批次内别名和截止时间构成，其配置哈希在工作区首次导入时冻结。投递 JSONL 以消息 ID、尝试号形成事件身份；同身份异内容进入冲突队列。原始行、来源文件和 SHA-256 留存。

数据流：冻结名单 → 投递事件导入 → 批次内地址归并 → 每消息状态重建 → 截止时效与撤回重发判断 → 逐人结论 → JSON/Markdown 送达证明。

每个消息从 `queued` 开始，可走 `sent`、`deferred`、`bounced`、`receipt` 或 `revoke` 的合法转移。无排队事件或非法跳转标记问题；回执事件时间晚于截止点标记 `late_delivery`。新消息的 `resends` 必须引用已出现的旧消息，旧退信事件继续保留。收件人可能有多个批次内别名，但未知地址不得自动归并到其他人。

结论为 `effective`、`undelivered`、`insufficient`；缺送达时间或状态证据不能推定有效。业务问题与结论可重算，原始投递史不可覆盖。当前只处理本地模拟投递日志，不发送真实通知。

## 现场核验派工

现场任务只对当前 `undelivered` / `insufficient` 且来源事件 SHA 与登记一致的目标开放。登记时同时留存原结论、原事件与来源摘要，以及本次资格快照的签名；决策重算后若某目标状态或来源改变，该目标资格失效、案件冻结、开放计划作废，已发生的到访观察保留不动。重新核对只允许仍为非有效结论的目标恢复派工，绝不把现场观察当成邮件回执。

计划与执行分表：计划按版本写入 `field_plan` / `field_plan_stop` / `field_plan_leg`（含目标、最优键与搜索完整性说明）；`field_move` 与 `field_inspection` 只追加实际动作，以调用方操作 ID 幂等。核验员位置只由已执行路段重建，计划本身不构成移动证据；每个地点至多检查一次，收工须在班次内到达收工点。

路网为有向加权边，`field_closure` 记录定向时段封闭，窗口内不可离站通行。规划器使用子集 DP：`(已访集合, 末站)` 状态上保留全部可能影响后续的标签，再枚举地点在至多两名核验员间的所有分配。`min_total_travel` 取（道路分钟总和，最大迟到）字典序最小；`min_max_lateness` 取（最大迟到，道路分钟总和）字典序最小。受件地址冲突或班次内不可达时报 `no_feasible_route`，不生成计划。
